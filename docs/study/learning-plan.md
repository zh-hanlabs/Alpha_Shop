> 定位：把「已经写完的项目」转成「本人能脱稿讲清的能力」。本文管**学习顺序与动手实验**；`project-overview-interview.md` 管**结论速查**（当字典用），`docs/resume/shopagent-bullets.md` 管**对外怎么写**。

## 0. 学习目标与终审闸

**这不是「读懂代码」计划，是「扛住追问」计划。**

项目为 AI 代写，代码与证据均已入库（140 单测、C1–C7 混沌、W7 压测双源、21 条踩坑实录），学习成本不在「写」而在「消化」。终审闸已由项目自己留好——`docs/resume/shopagent-bullets.md` §7 七项，其中硬闸一条：

> 每条 bullet 的「口径陷阱」能**主动**说出来，不等面试官追问。

**过闸标准（三条，全部可验证）**：

1. 三张图合上文档能画：五层架构图、一次对话时序图、TradeGuard 闸序图
2. 每个数字能说出处与口径（7.0 倍 / 96.67% / 735ms / 849.7ms…），并能当场打开证据文件对上
3. 每条设计决策能答「为什么不是另一种方案」（唯一索引为什么不够 / 限流为什么分布式而熔断进程内 / 库存为什么永不进缓存）

## 1. 使用节奏

- 每天 2–3 小时；赶时间走 §5 一周压缩版
- 每天结构固定：**读代码 → 查指南对答案 → 动手跑实验 → 自测产出**。顺序不能反——先读指南会得到「看懂了」的错觉
- 每阶段结束做一次「合上文档画图」，画不出就是没学会，回读
- `docs/study/project-overview-interview.md` 只在两个时机翻：① 读代码碰壁时查结论 ② 自测时对答案。不要通读

## 3. 每日安排

### D1 — 定位与跑通

**读**：主计划 §0 一句话定位、§3 路线图、§10 ADR-lite；README「核心能力总览」表；学习指南 §1（30 秒开场）、§3（五层架构 + 横切层）

**动手**：
- `docker compose up -d`，确认 redis / mysql healthy、app 启动
- 按 `docs/deploy/w8d5-demo-evidence.txt` 的 13 轮链路复走四场景：**查**（订单+物流）/ **问**（RAG 露营灯）/ **办**（下单）/ **退**（退款）
- 打开浏览器 DevTools，亲眼看 SSE 五类事件（thinking / tool / answer / error / done）到达顺序

**自测产出**：合上文档画五层架构图；一句话说清差异化（把 LLM 当不可靠调用方，正确性不靠模型自觉）

---

### D2 — 一条消息的生命周期

**读**：`controller/`（SSE 五类事件组装、userId 注入 ToolContext）→ `agent/ShopAgentGraph`（START→loadMemory→chat→persistMemory→END）→ System Prompt 三段结构 → 工具注册 → `resources/static/index.html`

**关键点（这三个是高频追问）**：
- 内部工具执行模式下工具调用块**不进流**，工具事件走 `ToolEventListener` 旁路推送
- token 流走 Sinks 旁路，**不穿图 state**（图 state 不能装「活对象」）
- SSE 必须发 `done` 事件，否则客户端通道不关

**自测产出**：脱稿画完整时序图；答「工具事件为什么走旁路」「图 state 为什么不能装活对象」

---

### D3 — 九个工具与安全防线

**读**：`tools/query/*`（6 个）+ `tools/trade/*`（3 个）；README「安全设计」7 场景表；AGENTS.md 分层铁律（tools 只做校验与编排，业务进 service，横切进 infra）

**动手**（用 u1002 越权素材 + 攻击话术，对照 README 边界测试）：
- 越权：以 u1002 身份查订单 10006（u1001 的单）→ 应返回「订单不存在」同话术
- 改价 / 假管理员 / SQL 注入诱导 → 应全部被工具层白名单拦下
- 观察：LLM 可能被话术诱导绕过 Prompt，但**工具层代码拦得住**

**自测产出**：答「安全为什么必须在工具层代码而非 Prompt」；答「他人订单与不存在为什么必须同话术」（存在性泄露）

---

### D4 — 交易安全三件套（上）：读透闸序 ★

**读**：`infra/guard/`（TradeGuard 统一闸序）→ `infra/idempotent/`（IdempotentExecutor 四态语义）→ `tools/trade/` 三个入口；对照 README 闸序 mermaid 图

**关键点**：
- 幂等键设计（`IdempotentKeys`）：placeOrder = 会话 + 指令摘要；退款 / 取消 = orderNo
- 幂等语义 = **返回首次结果而非报错**（防 LLM 重试死循环，AGENTS.md 已定决策）
- 锁粒度 = 用户 + 订单级
- 审计双出口：业务锁内随写 / 重放锁外即写；抢锁失败不审计（未进临界区）

**自测产出**：脱稿画闸序图并标出审计双出口；答「为什么返回首次结果而不是报错」

---

### D5 — 交易安全三件套（下）：实验取证 ★

**读**：`infra/lock/`（tryLock 3s + 看门狗续期、fail-closed）、`infra/audit/`（TradeAuditLogger 尽力而为不阻断）、`service/TradeService` 状态机条件迁移

**动手**（dev-only 端点直打工具层，绕过 LLM 保证并发确定性）：
- C1：同键 ×10 并发 → 仅 1 单落库、其余返回同订单号
- C2：异键 ×50 并发 → 零超卖、库存精确 -50
- C3：退款重放 ×10 → 库存只还一次
- 查 `trade_audit_log`：同幂等键两条审计记录
- `redis-cli MONITOR` 观察 EVALSHA（tryLock / unlock）与 hincrby

**自测产出**：学习指南 §11 交易安全类问答 + 三层追问 5 条（唯一索引 vs 前置拦截 / 看门狗与幂等正确性来源 / 幂等键为什么防误伤复购）

---

### D6 — RAG 与两级缓存

**读**：`infra/rag/` + `infra/cache/`；双模型路由（DeepSeek chat + DashScope embedding，SAA 路由键 `spring.ai.model.embedding.text` 三键组合才互斥共存）；缓存边界 = 展示字段、**stock 实时查库**；Cache Aside 先更库再删缓存

**动手**：
- 跑 `docs/rag/rag-cases.json` 10 题（含链式题 + 一道无关题）
- 重启前后对比冷热耗时（冷 53.8ms → 命中 6.8ms）
- 观察向量库指纹幂等：重启后指纹匹配则跳过重建

**自测产出**：答「只留 L1 / 只留 L2 的代价」「marker_hits=2 比直读 Redis 多证什么」「无关题为什么必须有一道」

---

### D7 — 稳定性三件套与压测数字

**读**：`infra/resilience/`；学习指南 §7（分级降级矩阵：知识库 fail-open / 交易 fail-closed）+ §9.1 压测矩阵 + §9.2 取数口径

**关键点（数字必须能说出处）**：
- 7.0 倍：热缓存 vs 冷回源（重启清 L1 + DEL L2 含真 dogpile；两个混淆因素怎么隔离；为什么 W8D4 把 10.2 倍改成 7.0 倍）
- 96.67%：限流全局桶 10/s，同形突发 300 请求拒绝率（**限流关/开同形对照**归因）
- 849.7ms：锁排队代价，非缺陷
- 96.5/s 桩链路 ≠ LLM 能力，两个口径分开讲

**动手**：从 `docs/jmeter/w7d2`、`docs/jmeter/w7d3` 挑一组 JTL 对照报告读，复算一个数字

**自测产出**：每个数字能说出处与口径；答「限流为什么分布式、熔断为什么进程内」；报数字前先声明单机口径

### D8 — 记忆与 Graph 编排

**读**：`infra/memory/RedisChatMemoryRepository`（field 按 `parseInt` 升序重建，不靠 Redis 字典序）、`agent/` Graph 并行查询节点（模型自主并行调 OrderQuery + Logistics）

**关键点**：为什么 InMemory 记忆 W6 必须换 Redis（无状态扩容）；Redis hash 为什么带序号 field；损坏条目的降级粒度

**自测产出**：学习指南 §11 架构与 Agent 类问答；答「为什么 InMemory 不够」

### D9 — 已知局限与真 bug 故事

**读**：学习指南 §12 三段式应答表 22 行、§9.3 四个真 bug 故事

**四个真 bug（面试讲故事首选，都是「回归价值」的证明）**：
1. 订单查询缺 userId 归属校验（W1D8，越权漏洞）
2. C3「还库存 ×2」根因链路（H2 时代踩不到）
3. Redis 停机不落盘（部署层 dir 与挂载点，W8D4 修复）
4. 「模型口头退款」——HTTP 200 却 toolCalls 为空（W8D5 钓出，三源互证）

**自测产出**：抽 5 条局限练习三段式（**没做的是排期问题，取舍的是设计判断**，两类不混）；两条硬时机：报压测数字前先声明单机口径 / 讲双层限流必主动讲 userId 无登录态；答「口头退款为什么正确名字是覆盖边界不是漏洞」

## 4. 方法论（四条）

1. **代码先于指南**：先读代码碰壁，再查指南对答案。记忆留存与「先看结论」完全不同
2. **每阶段「合上文档画图」**：架构图、时序图、闸序图三张是硬指标，画不出即回读
3. **混沌端点是免费实验场**：`/api/dev/chaos/*` 直打工具层绕过 LLM，改参数看行为，比读十遍代码有用
4. **对照证据学**：`docs/chaos`、`docs/jmeter`、`docs/cache`、`docs/rag`、`docs/resilience`、`docs/deploy` 里的文件就是面试讲故事的弹药库，学的时候就把「数字 ↔ 文件路径」绑定记忆
